EagleEye

A vision system that tells an FRC robot where it is on the field, from the AprilTags its cameras can see. It runs several cameras on a Raspberry Pi or similar Linux board, and teams set it up in a browser.

Code on GitHub Documentation

The problem

In FIRST Robotics Competition, robots drive themselves for the first part of each match and aim at targets the rest of the time. Both need the robot to know where it is. The field has AprilTags, printed square markers at known positions, so a camera that sees a tag can work out its own pose from it.

Doing that on a robot is harder than it sounds. Teams want several cameras for coverage, but they run on a small onboard computer next to everything else. Full-frame tag detection on every frame from every camera doesn't fit, a single bad detection can throw the pose off by metres, and each team's camera mounts are different, so a fixed pipeline doesn't work for everyone.

What I built

I started EagleEye in February 2024 and have written most of it: about 1,000 of its commits are mine.

  • A pipeline editor in the browser. Each camera's processing is a node graph: device input, detection, pose solving, filtering, and output to NetworkTables. Teams wire it up and tune it while the robot runs, with per-node timings on screen.
  • A Rust AprilTag detector, PnP refiner and outlier filter. The hot path moved out of Python into Rust modules, and the outlier filter rejects poses that disagree with the rest before they reach the robot.
  • Tag prediction. From the last camera pose and the field's tag map, a Rust preprocessor projects where each tag should appear and hands the detector only those regions. If none of them holds a tag, it falls back to one full-frame search, so coverage isn't lost.
  • Object detection on CPU, CUDA or MemryX MX3 accelerators, in the same graphs.
  • A robot-side library that reads EagleEye's poses and detections over NetworkTables.

How it's measured

Real match footage has no ground truth, so I built a synthetic benchmark. A Blender pipeline renders six 30-second robot routes on the CAD model of the 2026 field: 21,600 frames at 1280×800 and 120 FPS, with varied lighting and exposure, sensor noise, defocus, motion blur and lens distortion. The renderer checks the routes against the field geometry, and each frame comes with the camera's true pose.

Every frame is replayed through the same graphs the robot runs, full-frame and with tag prediction, using the production scheduler, detector and PnP. Each run writes per-frame pose and detection scores, pipeline and detector timings, and hashes of the dataset, graphs, calibration and environment, so two builds can be compared frame by frame.
